## 1. 库结构与定位方式

| 表 | 主键（BINARY、显式、非空） | 行数 | 用途 |
|---|---|---|---|
| `bench` | `code` | 3 | 父表，母版 `north/south` + 探针 `east` |
| `node` | 复合键 `(bench, slot)`，WITHOUT ROWID | 13 | 主材料，承载全部三类探针 |
| `binding` | `id` | 2 | 外键样本，含指向超大复合键的引用 |
| `type_probe` | `code`，STRICT + `ANY` 无亲和列 | 7 | 干净演示存储类型与比较归类 |

**浏览者用复合键找原值**：`node` 的每行都由 `(bench, slot)` 唯一标识。例如要找
「超出安全整数的复合键」那一行，用 `WHERE bench='east' AND slot=9007199254740993`；
在 Pagefold JSON 里对应的键是 `[["t","east"],["i","9007199254740993"]]`。
材料中每个值都能这样回溯到一个实际键，没有游离值。

## 2. 两种读法是什么

### 读法 A —— Pagefold 带类型 JSON（保真、前端安全）

文件：[`data/pagefold-export.json`](../data/pagefold-export.json)（整库）、
[`data/pagefold-rows.jsonl`](../data/pagefold-rows.jsonl)（逐行）。

每个单元格是一个**带标签的原子**，标签即真实存储类型，数值不经过 JS `Number`：

| 标签 | 含义 | 承载方式 | 例子 |
|---|---|---|---|
| `i` | 整数 | **十进制字符串**，规避 JS 精度 | `["i","9223372036854775807"]` |
| `r` | 实数 | IEEE-754 双精度 hex，可无损还原 | `["r","0x1.8000000000000p+1"]`（=1.5） |
| `t` | 文本 | 原字符串 | `["t","3"]` |
| `b` | BLOB | base64；空 BLOB 为空串 | `["b","Mw=="]`、空 BLOB `["b",""]` |
| `n` | NULL | 单元素 | `["n"]` |

### 读法 B —— SQLite 直连查询（原生动态类型）

文件：[`data/sqlite-view.jsonl`](../data/sqlite-view.jsonl)（逐行，含 `typeof()`）、
[`data/sqlite-equality.md`](../data/sqlite-equality.md)（比较归类实测）。

直连时 SQLite 按原生存储类型返回值，必须配合 `typeof()` 才能区分「显示相同、类型不同」
的单元格。这正是裸 SQL 客户端最容易误判的地方。

## 3. 三类必查材料，逐键定位

### 3.1 超出 JavaScript 安全整数范围的复合键

`Number.MAX_SAFE_INTEGER = 2^53-1 = 9007199254740991`。下列 `node` 复合键的 `slot`
都超出该范围，SQLite 以 64 位整数精确保存，Pagefold 用字符串原子精确保留：

| 复合键 `(bench, slot)` | slot 含义 | 裸 JS `Number(slot)` | 是否丢精度 |
|---|---|---|---|
| `('east', 9007199254740993)` | 2^53+1 | `9007199254740992` | 是 |
| `('east', 9223372036854775807)` | 2^63−1，SQLite 整数上限 | `9223372036854776000` | 是 |
| `('east', -9223372036854775808)` | 负向 2^63 | `-9223372036854776000` | 是 |

前端实测脚本：[`scripts/js_safe_integer_demo.js`](../scripts/js_safe_integer_demo.js)
（`node` 运行，退出码 0 表示环境确实无法用 Number 精确保存这些键）。
**建议**：前端一律走读法 A 的字符串原子，或使用 BigInt，不要把 `slot` 当普通 JSON 数字。

### 3.2 空 BLOB 与 NULL（两者都真实存在、互不相等）

| 复合键 | 列 | 实际存储 | `typeof()` | Pagefold 原子 |
|---|---|---|---|---|
| `('east', 100)` | `payload` | 空 BLOB `x''`（0 字节） | `blob` | `["b",""]` |
| `('east', 101)` | `payload` | NULL | `null` | `["n"]` |

母版锚点 `('south', 1)` 的 `payload` 同样是空 BLOB `x''`，与任何 NULL 都不同。
定位区别：`payload IS x''` 命中空 BLOB；NULL 只能用 `payload IS NULL`，
`payload = NULL` 永远取不到行（见 `sqlite-equality.md` 第 3 节）。

### 3.3 显示相同、存储类型不同的业务值

**`node.payload`（BLOB 亲和列，原值不被转换）**，四个键的渲染都像 `3`，但类型不同：

| 复合键 | `payload` 存储 | `typeof` | Pagefold 原子 | `payload = 3` |
|---|---|---|---|---|
| `('east', 200)` | 整数 3 | `integer` | `["i","3"]` | 1（真） |
| `('east', 201)` | 实数 3.0 | `real` | `["r","0x1.8...p+1"]` | 1（真，数值归并） |
| `('east', 202)` | 文本 '3' | `text` | `["t","3"]` | 0（假） |
| `('east', 203)` | BLOB x'33' | `blob` | `["b","Mw=="]` | 0（假） |

无亲和探针表 `type_probe` 给出同样的四态（键 `num-int / num-real / num-text / num-blob`），
外加 `empty-text('')`、`empty-blob(x'')`、`null-sample(NULL)`，用于排除亲和干扰、单独验证类型。

## 4. 哪些列在 SQLite 比较时会被归为一起

SQLite 是动态类型库，比较遵循**存储类型 + 列亲和**规则（实测见
[`data/sqlite-equality.md`](../data/sqlite-equality.md)）：

1. **整数与精确等值的实数归为一个比较类**：`3 = 3.0` 为真；`GROUP BY` 把
   `num-int` 与 `num-real` 并进同一组。但 `typeof()` 仍分别是 `integer` / `real`，
   Pagefold 也分别给 `i` / `r` 标签——**比较归并不等于类型相同**。
2. **文本与 BLOB 各自独立**：`'3' = x'33'` 为假、`'' = x''` 为假、`'3' = 3` 为假。
   即便字节或显示相同，text 与 blob 永不互相归并。
3. **NULL 不参与等值**：`NULL = NULL` 结果是 NULL（非真），只能用 `IS NULL` 定位；
   因此 NULL 不会与任何值（包括另一个 NULL）通过 `=` 归并。
4. **整数亲和主键会归一实数键**：向 `node.slot`（INTEGER 亲和）写 `4.0`，实际存成
   整数 `4`（键 `('east', 4)`，`typeof(slot)=integer`），再插 `4.0` 会触发唯一约束。
   这与 Pagefold `rows.key_atom` 的行身份规则一致：主键里精确等值的整数/实数视为同一行。
5. **列亲和会改变存储类型**：`node.weight` 是 REAL 亲和，写入整数 `1` 也会存成
   实数 `1.0`；要保留「整数 3 vs 实数 3.0」的原始区别，需使用 BLOB 亲和列
   （`node.payload`）或 STRICT `ANY` 列（`type_probe.sample`）。

## 5. 复算与核查方式

```sh
# 重新构建镜像（确定性输出，sha256 应与上文一致）
python3 -I deliverables/scripts/build_mirror.py deliverables/data/node-reference.sqlite

# 读法 A：Pagefold 带类型 JSON
python3 -I deliverables/scripts/export_pagefold.py \
  deliverables/data/node-reference.sqlite deliverables/data

# 读法 B：SQLite 直连视图 + 比较归类
python3 -I deliverables/scripts/export_sqlite_view.py \
  deliverables/data/node-reference.sqlite deliverables/data

# 交叉核查（Pagefold 登记链路 + 两读法逐键逐类型比对，8 项全过才退出 0）
python3 -I deliverables/scripts/cross_check.py \
  deliverables/data/node-reference.sqlite \
  deliverables/data/pagefold-rows.jsonl \
  deliverables/data/cross-check-report.json

# 前端精度风险演示
node deliverables/scripts/js_safe_integer_demo.js
```

`cross_check.py` 内部同时调用了真实的 Pagefold 登记（`images.register` →
`catalog.describe` / `check_database` / `read_image`），确认该镜像满足可登记要求：
显式非空 BINARY 主键、无视图/触发器/生成列/AUTOINCREMENT、完整性与外键检查通过、
在 4 MiB / 32 表 / 20000 行限额内。镜像也已通过真实 HTTP 入口
`POST /api/images` 验证可上传登记。
